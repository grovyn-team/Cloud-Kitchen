# CRITIQUE 005 — D-007: Tax module scope (GST India) + repositioning

**Verdict: Endorse — Significant (repositioning) / Minor (scope).**

## 1. The decision, restated
Two decisions: (i) scope — GST-India only at launch + a jurisdiction abstraction
seam; (ii) liability posture — reposition from "provide a valid audit" (brief's
language) to "prepare and reconcile data for the client's CA, CA in the loop, not
a substitute for one."

## 2. Goal alignment
**O4 (Trust it)** — the repositioning is pure liability-risk reduction.

## 3. Strongest case for
Building one jurisdiction well beats two badly; the seam prevents a rewrite
(YAGNI-with-a-hinge). And the brief's "provide a valid audit" is a genuine
overclaim: GST audit/certification (GSTR-9C reconciliation) is regulated CA work
in India; software emitting authoritative filing figures invites liability when a
figure is wrong. CA-in-the-loop prep/reconciliation is the correct, honest
framing.

## 4. Strongest case against
The "abstraction seam" is where "build for one, hinge for two" quietly becomes a
generic tax framework nobody asked for — keep it an **interface boundary**, not a
plugin engine. And under-claiming has a cost: as a pure data-prep tool, is the
Tax Assistant still a Phase-6-worthy differentiator, or a thin export-to-CA
feature?

## 5. The cost nobody mentioned
Positioning is a **product + contractual** commitment, not a design note. The
disclaimer must land in **UI copy, generated report headers ("Prepared for CA
review — not a certified filing"), and the Terms of Service**, or it provides
zero legal protection. A caveat that never reaches the user-facing artifact is
decorative.

## 6. Reversibility
Scope is **two-way** (add jurisdictions later). A **claim already made to a
client** is one-way — you can't un-tell an enterprise buyer "we do your GST
audit."

## 7. What would have to be true for this to be wrong
That an overclaimed compliance feature is worth more than an honest one. It isn't,
especially to an enterprise buyer whose own CA/legal will scrutinize the claim.

## 8. Verdict detail
Endorse both. Non-optional: propagate the repositioning to UI copy, report
disclaimers, and TOS; constrain the seam to an interface, not a framework. The
user is already taking professional advice — correct.

*Objection tried:* "repositioning deflates the module's value." *Fails:* a
liability-creating overclaim is worth *less* than an honest prep tool to the buyer
who matters.
