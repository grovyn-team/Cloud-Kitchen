# SECURITY_REVIEWS/004 — P1-04 Authentication (independent OWASP review)

Reviewer: security-engineer (independent). Method: static verification against
actual source PLUS dynamic probing on a throwaway Postgres 16 container
(migrations 0000-0005 + bootstrap-roles applied, `grovyn_app`/`grovyn_migrator`
privilege split). The implementer's 55-check `tests/auth.pgtest.mjs` was run and
all 55 passed on a clean container; I additionally ran my own SQL/param probes
rather than trusting the green suite. **I CONCUR** with the implementer's
self-reported verification, with the follow-ups below.

## Verdict: CLEAR WITH FOLLOW-UPS

No Critical or High findings. P1-04 may move to `Done`. Follow-ups are Medium/
Low and are either out of P1-04's declared scope (rate-limiting, P1-05 route
wiring) or hardening nice-to-haves; none are exploitable as shipped.

## What I verified independently (not just read)

- **A07 argon2id params** — produced a real hash: `$argon2id$v=19$m=65536,t=3,p=4`
  (64 MiB / t=3 / p=4). Exceeds OWASP minimums. Correct algorithm (argon2id),
  not a weaker one. (`passwordService.js`)
- **A07 timing oracle** — measured medians on the container: unknown-user 91.6ms
  vs wrong-password 91.8ms (delta ~0.2ms) — the security-critical email-
  enumeration channel CRITIQUE 017 found is genuinely closed. `dummyVerify()`
  runs a real argon2id verify on tenant-not-found and user-not-found paths;
  wrong-password runs the real verify; every failure path pays exactly one
  argon2id op and returns a byte-identical 401. Confirmed at all call sites in
  `authService.js`.
- **A07 tokens** — 256-bit `crypto.randomBytes(32)` (CSPRNG), base64url; only
  SHA-256 `token_hash` stored (fast hash correct for a high-entropy secret).
  Unique index `session_token_hash_unique_idx` present. Refresh rotates in place
  and the OLD token is rejected post-rotation (verified live: 401). Logout soft-
  revokes; revoked token rejected (verified live). No dual-valid window.
- **A07 SESSION_SECRET** — no fallback anywhere (`grep`), `config/index.js`
  throws at import if unset; confirmed live (fresh process with empty secret
  throws, cites SESSION_SECRET).
- **A01 role-from-DB-only** — `requireSession` sets `req.userRole` strictly from
  the resolver row; login response role from the DB record. Live test:
  `login` with body `role:"ADMIN"` for a STAFF user returns STAFF. Grep of all
  `role` usages in `src/` shows no real-auth path reading role from
  req.body/headers/query.
- **A01 branch scope** — `requireBranchAccess` derives scope from
  `req.branchIds` (resolver aggregates `staff_branch_access` with
  `revoked_at IS NULL`, scoped `sba.user_id = s.user_id AND sba.tenant_id =
  s.tenant_id`). Live: staff allowed to assigned branch, 403 to unassigned;
  ADMIN implicit all-branch within own tenant.
- **A01 RLS on 0003/0004** — `relforcerowsecurity = t` on branch,
  staff_branch_access, session. `grovyn_app` with no tenant context reads 0 rows
  from all three (fail-closed). Grants are exactly SELECT,INSERT,UPDATE — no
  DELETE (DELETE denied at privilege layer, verified live). Tenant-isolation
  USING+WITH CHECK predicate matches the P1-01 pattern.
- **A03 SECURITY DEFINER (0005)** — `prosecdef=t`, `proconfig=search_path=""`,
  owner `grovyn_migrator` (BYPASSRLS), fully schema-qualified
  (public.session/public."user"/public.staff_branch_access), no dynamic SQL,
  parameterized, EXECUTE revoked from PUBLIC and re-granted only to grovyn_app.
  Matches D-015 rigor. Call sites pass `hashToken(token)` as a bound param.
- **A02 secrets** — no token/password/hash written to any log or response beyond
  the intended token delivery in the login/refresh response body. `auditService`
  stores action/entityType/entityId/reason only.
- **Demo gate** — routes are conditionally mounted (`if
  (config.auth.demoModeEnabled)` in `routes/v1/index.js`), default false
  (`AUTH_DEMO_MODE === 'true'`, strict). Live: 404 when disabled, 200 when
  enabled — structurally absent, not present-but-denying.

## Findings

- **F1 (Medium, A07) — No brute-force / rate-limiting on `/auth/login`.** No
  account lockout or request throttle; argon2's ~90ms cost is the only natural
  brake. Likely out of P1-04's declared scope but A07 calls for it. Recommend a
  per-(tenant,email) and per-IP throttle + lockout on repeated failure. Track
  as a follow-up task, not a P1-04 blocker.
- **F2 (Medium, A01/A07) — Legacy HMAC token middleware still mounted on all
  business routes.** `middleware/authMiddleware.js` (`authOptional`,
  `requireAuth`, `requireRole`, `requireStoreAccess`) reads `role`/`storeIds`
  from a client-held signed token payload — the exact anti-pattern P1-04
  replaced — and still gates every `/api/v1/*` business route in
  `routes/v1/index.js`. NOT exploitable as shipped: the only issuer of legacy
  tokens is the demo login (gated off by default), forging one needs
  SESSION_SECRET, and real random session tokens fail the HMAC verify — so with
  demo off these routes accept no token at all. P1-05 must migrate business
  routes to `requireSession` and retire the legacy path. Follow-up for P1-05.
- **F3 (Low, A07) — argon2 relies on library defaults.** Only `{ type:
  argon2id }` is passed; memory/time/parallelism come from node-argon2 defaults
  (currently strong). Pin `memoryCost`/`timeCost`/`parallelism` explicitly so a
  future dependency bump can't silently weaken them.
- **F4 (Low, A09) — Unknown-tenant login failures are console-only, not in
  `audit_log`.** Justified (audit_log is tenant-scoped, `tenant_id NOT NULL`),
  but cross-tenant slug-spray / tenant enumeration attempts aren't in the
  queryable trail. Consider a separate non-tenant-scoped security event sink.
  Product/infra decision — route to DECISIONS_LOG for Project Master.
- **F5 (Low/Info, A02/A05) — `DEMO_PASSWORD` literal `'grovyn@123'` committed**
  in `routes/auth.js`. Only reachable in demo mode (gated off) and never wired
  to the real `user`/`session` tables (in-memory only). Acceptable, but the
  committed default credential should be removed once demo login is retired.
- **F6 (Info, A07) — Timing reveals tenant existence** (~20ms faster on
  unknown-tenant, measured 71.8 vs 91.6ms — one fewer DB round trip + no audit
  write). Acceptable: the tenant slug is already public (subdomain/URL), and the
  security-critical user-enumeration channel is closed (F above). No action.

## Note on gate coexistence

P1-04 delivers the correct DB-backed auth primitives, but they are only wired
into `/auth/*`. Business-route authorization still runs on the legacy path (F2).
This is consistent with the task's stated scope boundary ("P1-05 owns wiring
requireSession into real branch-scoped endpoints"), so it does not block P1-04 —
but P1-05's security review must confirm the legacy middleware is fully retired,
or the role-from-DB guarantee proven here does not yet protect real data reads.
